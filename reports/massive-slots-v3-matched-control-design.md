# v3 后续对照：同样新增样本的继续 SFT

状态：**已看到 v3 DPO 的开发集结果后设计，属于探索性方法对照。** 本方案在对照模型训练与推理前公开；它不改变 v3 DPO 未通过门槛的结论，也不解锁原先封存的 400 条确认集。开发集此前已用于 v2/v3 错误分析，因此无论本对照的数值如何，都只能作为解释机制的开发集证据，不能称为独立确认。

## 问题与固定数据

v3 DPO 相对 v2 SFT 将无槽失败从 126/167 降至 28/167，但阳性子集 F1 从 67.01% 降至 54.75%。因为 v3 也加入了 256 个全新训练组，目前无法分辨这种变化来自新增标注、DPO 目标还是两者组合。对照只取已冻结的 256 对偏好样本中的 `prompt` 和正确 `chosen`，转为 SFT 的 `prompt`/`completion`；不重新抽样、不读 DPO 错误回复、不增加原句、不使用开发集/确认集作训练。源偏好文件 SHA-256 `310c26b37fd7eee7cbfb4876def2d398fcd5f0d188a24da20b24aa474471c450`，其 manifest SHA-256 `5f20af854896b61e38ad2eda3b73f49c195f58afda0a01a8bb1dff6b6007f33a`。派生的 256 条继续 SFT 文件 SHA-256 **`8de93fdabe1b580def8bb10bef6e6cdb05942ff621bc29c0e7a34db1f0eed25c`**，逐项与 DPO 的训练组对应。真实 TRL 模板和 completion 掩码已在全部 256 条上核查，最长完整序列 145 token，设定 256 token 不截断。

## 固定训练与比较

从**同一个** v2 第 160 步 Qwen2.5-0.5B-Instruct SFT adapter 继续训练，起始权重 SHA-256 `206bc1eee5115e20844e22fa146893c9f651058709c6aff5f15e77ec63f61ce6`。使用相同 CPU 4-bit QLoRA 基座与 tokenizer、batch 1、梯度累计 4、最大长度 256、随机种子 `20260930`，学习率 `1e-5`，训练 **64 optimizer steps（256 条各一次）**，第 32 步仅保存恢复点，**只评最终第 64 步**。不因训练 loss 或中途模型调整步数。运行清单记录训练文件和起始 adapter 的哈希；如有中断，只从完整的优化器、scheduler 和 RNG 检查点恢复，并披露偏离。最终 adapter 的保存精度需在开发集推理前公布。

固定在 v2 的 250 条自然频率开发集上用与 v3 DPO 相同的自由贪心设置推理一次。报告 JSON/结构/复制合法率、严格实体 micro-F1、阳性子集 F1、无槽失败、逐句正确率，并以原句组配对 bootstrap 1000 次、种子 `20260929` 给出两个主比较：继续 SFT 相对 v2 SFT，以及 v3 DPO 相对继续 SFT 的实体 F1 差值和无槽失败下降。冻结 v2 BIO 仅作为参考。逐题预测保留本地，公开聚合结果与哈希。不能以此开发集结果反选 v3 模型或对现有确认集推理。

这个对照控制了新增训练组和起始 adapter，但 SFT 与 DPO 的损失函数不同，`chosen/rejected` 结构与单一正确答案不同；相同 optimizer steps 不等于相同 token 梯度或计算量。若保存精度不同，也应在报告中单独列明。它能提供比 v2/v3 直接比较更好的方法解释，仍不是严格的 DPO 因果消融或线上质量证明。
