# 四槽抽取 v3：针对无槽误报的偏好优化方案

状态：在 v2 开发集失败分析和 v3 候选数据构造后、v3 偏好响应生成及训练前冻结。**v2 的 400 条确认集仍未用于推理或评分。** 本轮开发集沿用已被分析过的 v2 dev，因此开发集结果只能用于选型；若达门槛，必须再进行一次独立确认。

## 为什么做这一轮

v2 第 160 步 SFT 在自然频率开发集上严格实体 F1 为 42.17%，无目标句失败 126/167；同量 BIO 分别为 61.76% 和 9/167。事后在同一开发集试过 BIO 门控、二分类门控及少数 place_name 组合规则；最佳简单组合的 F1 为 64.08%，比 BIO 高 2.31 个百分点，但配对 95% 区间为 −1.19 至 +5.86，跨 0。因此这些开发集探索不作为确认集解锁依据，也不作为性能成果。v3 检验一个新的训练假设：给冻结的 v2 SFT 提供更多未见训练原句上的正确/错误回复偏好，是否能学习在无目标句输出空列表，同时保留目标实体抽取。

## 来源、隔离和固定候选池

原始来源仍为 MASSIVE 1.0 `zh-CN` 官方 train，数据许可 CC BY 4.0；归档 SHA-256 `7df623fd2d300a4d235d6ee5bd396c9a28258d3a0ccb29abdb054506eba153f8`。`scripts/prepare_massive_slots_v3_preferences.py` 沿用 v2 的强归一化分组和旧样本排除规则。它只从 v2 manifest 读取三切分的 **1,290 个组哈希**，在解析标签前排除这些组；不读取 v2 confirmation JSONL。还排除旧意图训练、四槽 v1 全部样本和官方 dev/test 的同组文本。

候选抽样种子 `20260930`，得到 **576** 个全新 train 来源组：`date/time/place_name/person` 各 48 个阳性，加 192 个含非目标槽位的困难负例和 192 个纯负例。候选 JSONL SHA-256 为 `2fc7e03e67417b4817bfcc3a557d0f1e950015e141e8cfdf26664214bd2e0c0f`，本地 manifest SHA-256 为 `493a4743b974cad98fc42e9535839b6d5e4c7fa60e1d0bb980eb08bcbd0db26d0`；两者在 Git 忽略目录，不公开原句或 source ID。候选池与 v2 train/dev/confirmation 强归一化组交集为零。

从候选池按固定哈希排序选 `date/time/place_name/person` 各 16 个阳性、困难负例 96 个、纯负例 96 个，共 **256** 个偏好对；选择与模型输出是否正确无关。对每条候选，用冻结 v2 第 160 步 adapter 自由贪心生成（batch 8、输入最多 256 token、最多新生成 64 token）。`chosen` 是 MASSIVE 标注转换的严格四槽 JSON；若模型原回复与标注不一致且长度合规，则 `rejected` 用原回复，否则用固定规则构造一个不同的、结构合法且值来自原句的错误回复。每对必须有相同 prompt、不同 chosen/rejected，并记录模型和数据哈希、原回复来源与退回构造数量。逐题原回复和偏好数据只存本地忽略目录。偏好对只能来自新候选 train 组，不得从 dev 或 confirmation 采样。

## 训练和门槛

从 v2 第 160 步 adapter 出发，其 `adapter_model.safetensors` SHA-256 固定为 `206bc1eee5115e20844e22fa146893c9f651058709c6aff5f15e77ec63f61ce6`；DPO 的冻结 reference adapter 使用同一份起始 SFT 权重，而非裸基座。Qwen2.5-0.5B-Instruct 基座及 tokenizer SHA-256 分别为 `fdf756fa7fcbe7404d5c60e26bff1a0c8b8aa1f72ced49e7dd0210fe288fb7fe`、`c0382117ea329cdf097041132f6d735924b697924d6f6fc3945713e96ce87539`。在 CPU 上运行 4-bit QLoRA DPO：`beta=0.1`、学习率 `1e-5`、单设备 batch 1、梯度累计 4、最大序列 256 token、种子 `20260930`、**64 optimizer steps**；第 32 步仅供诊断，最终只评估第 64 步。训练前须对全部 256 对执行真实 tokenizer 长度和结构检查；若任一超限，停止并在改计划后重新公开说明，不能悄悄截断。

开发集仍为 v2 的 250 条，固定自由贪心生成设置和严格实体计分。第 64 步必须同时满足：JSON／结构／原文复制合法率各 **≥95%**，无目标失败率 **≤30%**，总体严格实体 F1 **≥55%**，阳性子集 F1 **≥60%**；并且相对冻结 v2 第 160 步的配对组 bootstrap 95% 区间中，实体 F1 差值和无目标失败率下降的下界均 **>0**。任一不满足则停止，不生成新选择锁、不打开确认集。这些是本轮训练结果的门槛，不追溯改变 v2 失败结论。

若开发集全部过门槛，先冻结完整数据、基座、初始及 DPO adapter、tokenizer、推理代码、生成设置、开发报告和逐题预测的 SHA-256，然后才允许对原先封存的 400 条确认集各运行一次：v3 DPO、冻结 v2 SFT、同量 BIO。主要比较固定为 v3 对 v2 SFT，BIO 为参考；成功条件仍要求确认集实体 F1 和无目标失败率的配对区间下界均 >0，且 v3 绝对无目标失败率 ≤30%。确认集不得用于选步数、改偏好对、修规则或调门槛。即使达到研究门槛，云端自动抽取还需要真实请求、延迟与拒判验收。

本轮 DPO 使用新增训练组，不能把 v3 与 v2 的差异单独解释为 DPO 目标的因果作用；要分离数据增量效应，未来需另做相同新增样本的继续 SFT 对照。所有原始数据、逐题预测和权重仍不进入公开仓库。
