# 同样本继续 SFT 对照：v3 DPO 的拒判收益与召回代价

**结论：探索性开发集对照，不是新的确认成绩。** 用与 v3 DPO 完全相同的 256 个新增训练组的正确答案继续 SFT 后，总体严格实体 F1 为 **49.24%**，高于原 v2 SFT 的 42.17%；无槽失败从 **126/167** 降到 **78/167**。同样新增数据下，v3 DPO 的无槽失败进一步降至 **28/167**，但阳性句 F1 从继续 SFT 的 **67.36%** 降至 **54.75%**。DPO 相对继续 SFT 的总体 F1 差值为 **−2.13 个百分点**，配对区间跨 0。结果支持“新增正确答案本身能改善一部分错误；DPO 呈现更强的拒判倾向及阳性抽取损失”这一开发集观察，仍不能严格分离损失函数、回复结构、token 计算量与保存精度的作用。

## 先固定的对照

[对照设计及训练偏离记录](massive-slots-v3-matched-control-design.md)在此次 SFT 开发集推理前公开。256 条 SFT 数据逐项取自冻结偏好对的 `prompt` 与正确 `chosen`，不使用 `rejected`、开发集或确认集。派生训练文件 SHA-256 `8de93fdabe1b580def8bb10bef6e6cdb05942ff621bc29c0e7a34db1f0eed25c`。从同一 v2 第 160 步 SFT adapter（SHA-256 `206bc1eee5115e20844e22fa146893c9f651058709c6aff5f15e77ec63f61ce6`）开始，固定 64 optimizer steps、学习率 `1e-5`、batch 1、梯度累计 4、最大 256 token、种子 `20260930`。

首次训练在第 31 步后意外结束且无恢复点，未作开发集推理。按事先公开的偏离记录从相同起点重跑，只把保存间隔从 32 改为 8；重跑完整到第 64 步，没有再恢复。运行清单 SHA-256 `82e209eeb4e92efb5b151bef5e6b3eb0596062189357bbf066a88db5ed3c7480`，最终 adapter SHA-256 `97aa3eaf5ea19442f0c50bdd9048807b9de9a931fe86f17a11eb578e1e3343fc`，保存精度 `bfloat16`。这些指纹在开发集推理前已公开。原 v2 起点为 `float32`；v3 DPO 最终 adapter 同为 `bfloat16`。

## 解释边界与决策

这个 SFT 对照是**看过原 v3 DPO 开发集结果后设计**的；同一开发集之前也用于 v2/v3 分析。即使配对区间不跨 0，也只是当前开发集的探索性描述，不是独立确认。SFT 与 DPO 的损失、`chosen/rejected` 使用方式及计算量不同，不能把剩余差异唯一归因为 DPO 损失。继续 SFT 的复制合法率 **93.6%**、无槽失败 **46.71%**，都不满足原 v3 的 95%／30% 门槛；v3 DPO 也因总体和阳性 F1 未通过门槛。**两者均不产生选择锁，不评测封存的 400 条确认集，不作为自动槽位抽取服务。**

本结果对后训练研究的价值在于明确了下一步问题：增加同一批正确答案已改善总体 F1 和部分无槽错误；若继续研究偏好优化，需要在新的开发集上事先规定阳性召回保护与方法比较，再考虑独立确认。当前分数不得用于反选本轮检查点或修改已封存的确认集规则。
