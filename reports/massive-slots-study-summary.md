# 中文四槽抽取：本地 QLoRA SFT 与严格评测

本研究检验：在 16 GB 内存、无独立 GPU 的本机上，对 Qwen2.5-0.5B-Instruct 做 4-bit QLoRA SFT，能否把中文语音助理请求转换成可逐字核对的 JSON 槽位。它是后训练研究，**不是当前人工复核服务所部署的模型**。预注册方案见 [SLOT_RESEARCH.md](../SLOT_RESEARCH.md)，模型选择在打开确认集预测前写入 [selection lock](massive-slots-selection-lock.json)。

## 数据、许可与评价

数据来自 [MASSIVE 1.0](https://github.com/alexa/massive) 的 `zh-CN` 官方 **train** 分区，许可为 CC BY 4.0。只抽取 `date`、`time`、`place_name`、`person`，预测值必须是原句的连续子串。固定种子 `20260928` 构造 **384 train / 100 dev / 200 confirmation**，按归一化原句分组，组间不重叠；开发集和确认集还排除了旧意图 SFT 使用的 594 条训练原句。全部原句、逐条预测和模型权重保存在 Git 忽略目录，公开仓库只有可复现代码与聚合指标。

主指标是严格 `(type, 原文 value)` 多重集合实体 micro-F1。非法 JSON、错误结构和非原文复制按预测失败计，同时报告逐句全对率、格式有效率和无槽句误报。Qwen 基座与 SFT 用相同提示、自由贪心生成、输入上限 256 token、输出上限 64 token、batch 8；没有预测后修复。BIO 基线用同一 384 条训练数据拟合字符级 LinearSVC，约束 BIO 解码。

## 训练与开发集模型选择

本机 4-bit QLoRA 使用 LoRA rank 8，目标模块为 `q/k/v/o_proj`，学习率 `3e-4`，线性退火，训练 96 optimizer steps，保存第 48 步和第 96 步。训练用时 **6071 秒（约 101 分钟）**；最终训练 loss 为 `0.1731`。训练 token accuracy 含大量 JSON 语法 token，不能代替实体抽取指标。

| 开发集 100 条 | 实体 micro-F1 | 逐句全对 | JSON 合法 | 无槽误报 |
| --- | ---: | ---: | ---: | ---: |
| Qwen 基座 | 0.0% | 0.0% | 46.0% | 1/20；另有 19/20 非法输出 |
| QLoRA SFT，第 48 步 | 57.51% | 37.0% | 100% | 18/20 |
| QLoRA SFT，第 96 步 | **58.15%** | 39.0% | 100% | 15/20 |
| 字符 BIO + LinearSVC | 60.75% | 52.0% | 100% | 0/20 |

预先规定按严格实体 micro-F1 选择两个 SFT 检查点，平局优先第 48 步；因此选第 96 步。第 96 步只比第 48 步高 **0.64 个百分点**，按原句组配对 bootstrap 的差值 95% 区间为 **−4.50 至 +5.52 个百分点**，不能声称额外训练有可靠增益。第 96 步比基座高 **58.15 个百分点**，配对区间 **+50.00 至 +66.35**；严格格式遵循从基座的 9% 结构合法率升至 99%。BIO 与 SFT 的开发集 F1 差距区间跨 0。详见 [开发集配对比较](massive-slots-dev-comparison.json)及 [第 96 步错误汇总](massive-slots-sft-step96-dev-badcases.json)。

第 96 步的开发集错误包括 **15/20** 无槽句误报、7 条非原文复制和 1 条结构不合法；`time` 的逐类 F1 只有 **30.0%**。本研究不以训练 loss 或格式合法率替代语义准确率。

## 冻结确认集

第 96 步 adapter、基座、tokenizer、BIO 模型、数据清单以及生成设置的 SHA-256 已固定在 [selection lock](massive-slots-selection-lock.json)。确认集入口要求显式解锁并核对对应文件哈希；200 条确认数据只评一次，不用于二次调参。

| 确认集 200 条 | 实体 micro-F1 | 逐句全对 | JSON 合法 | 无槽误报 |
| --- | ---: | ---: | ---: | ---: |
| Qwen 基座 | 2.55% | 0.0% | 48.0% | 0/40 有效误报；40/40 输出无效 |
| QLoRA SFT，第 96 步 | 60.43% | 40.0% | 100% | 34/40 |
| 字符 BIO + LinearSVC | **68.05%** | **57.5%** | 100% | 7/40 |

SFT 相对基座的实体 F1 提高 **57.88 个百分点**，按原句组配对 bootstrap 的 95% 区间为 **+50.39 至 +64.44**，支持本轮任务适配收益。BIO 的点估计比 SFT 高 **7.61 个百分点**，配对区间为 **−0.06 至 +15.13**，下界略低于 0，不能声称其 F1 优势已达到预设的 95% 把握；但 BIO 的无槽误报少 **27/40**，逐句全对高 **17.5 个百分点**，且不产生非法输出。[确认集配对比较](massive-slots-confirmation-comparison.json)

SFT 的单模型实体 F1 组 bootstrap 95% 区间是 **53.95%–66.10%**；BIO 为 **61.68%–74.26%**。SFT 的 JSON 合法率虽为 100%，结构合法率为 97%、原文复制合法率为 92.5%；40 条无槽句中 34 条有效误报、其余 6 条输出无效，**40/40 都未正确拒判**。因此不能作为自动执行或无人复核抽取服务。基座的 40 条无槽句也全部输出无效；表中的 0/40 不是好的拒判表现。基座评测期间电脑暂停，其记录的墙钟用时包含暂停时间，不能与其他模型的纯运行时间比较。

## 外推边界与岗位价值

这是刻意富集目标实体的挑战集：开发集和确认集各有 80% 的句子含目标实体，官方源 train 约为 32%；F1 和无槽误报不能直接解释为真实请求流量的表现。新确认集的 3/200 条归一化原句与旧项目曾用的官方 dev/test 重合；确认集文本及标签也曾用于聚合重叠审计，但模型预测在选择冻结前没有运行，因此这里称“确认集”，不称绝对未见盲集。[重叠敏感性审计](massive-slots-overlap-audit.json)显示，去掉旧分区重合的 2 条开发集样本后，第 96 步 F1 为 58.04%，与全部 100 条的 58.15% 接近；去掉确认集重合的 3 条后，SFT/BIO F1 分别为 **60.04%/67.60%**，与全量结论相近。确认集敏感性分析是事后检查，不能替代新盲测。

项目可展示本机受限资源下的参数高效 SFT、许可和数据划分管理、严格 JSON/复制约束评测、配对不确定性、负结果与强基线比较。它**不证明**模型达到生产抽取质量，也不等同于大规模分布式训练或 Agentic RL 经验。下一轮若要提高效果，应先补自然频率与未知请求评测，再针对无槽误报和时间槽边界做新训练；新方案需使用新的开发/确认划分，不能反复消费本轮确认集。
