# 四槽抽取 v4：提高阳性偏好占比的预先方案

状态：**新开发集推理前冻结**。原 v2 的 400 条确认集继续封存。本轮另建独立确认集；在通过下面的开发集门槛且模型、推理代码与开发集报告锁定前，不读取其逐条内容或运行推理。

## 动机和单一候选

在反复分析过的 v2 开发集上，v3 DPO 将无槽失败显著减少，但阳性子集 F1 只有 54.75%；同样本继续 SFT 的阳性 F1 为 67.36%，无槽失败却为 46.71%。逐句对比发现 v3 DPO 没有独立答对任何一个另外两个 SFT 都答错的阳性句。v3 偏好对只有 64/256（25%）为阳性。这提示偏好训练的阳性覆盖不足，但不能证明因果。

仅训练**一个**新 DPO 候选：在全新的 256 个训练原句组上，将阳性比例提高为 128/256（50%），四种目标类型各 32 个；困难负例和纯负例各 64 个。其余模型、初始 adapter、偏好构造、优化设置和自由贪心生成保持与 v3 相同。只评最终第 64 步。若结果失败，不在本轮反选中途检查点、改阈值或二次调参。

## 训练和预先定好的评测

从冻结的 v2 SFT 第 160 步 adapter 开始（权重 SHA-256 `206bc1eee5115e20844e22fa146893c9f651058709c6aff5f15e77ec63f61ce6`），用相同 adapter 作 DPO 冻结 reference。`scripts/build_massive_slots_v4_preferences.py` 先对每条新训练句取得 v2 模型回答：答错且总长度不超过 256 token 时作为 `rejected`，否则用固定错误答案；正确标注为 `chosen`。全部偏好对检查模板、原文复制和长度。

训练固定为 Qwen2.5-0.5B-Instruct CPU 4-bit QLoRA，`beta=0.1`、学习率 `1e-5`、batch 1、梯度累计 4、最大长度 256、种子 `20261001`、64 optimizer steps，定期保存仅用于故障恢复。不能根据 loss 或开发集改步数。

在新开发集上分别推理 v3 DPO 冻结 adapter 和 v4 最终 adapter，使用 batch 8、输入上限 256、新生成上限 64、自由贪心生成。严格实体 micro-F1 按 `(type, 原文逐字值)` 多重集计，非法 JSON／结构／复制输出得零匹配；同时报告阳性子集 F1、无槽失败和合法率。组配对 bootstrap 1,000 次、种子 `20261001` 比较 v4 减 v3 的 F1。v3 因较早的训练组与 v4 不同，差异不能单独归因于阳性占比。

**开发集解锁门槛须全部满足：**v4 的严格实体 F1 ≥55%、阳性子集 F1 ≥60%、无槽失败率 ≤30%、JSON／结构／复制合法率各 ≥95%，且 v4 相对 v3 DPO 的配对 F1 差值 95% 区间下界 >0。若全部通过，先公开并锁定模型和代码指纹、开发集报告与选择结果，再只运行一次新 400 条确认集，原 v2 确认集仍不动。确认成功还需在新确认集上满足同样绝对门槛和相对 v3 DPO 的配对 F1 区间下界 >0。若任一条件未达标，完整报告失败，不把训练集或开发集数值称为独立性能提升。

本轮只检验一个明确的训练假设。不同训练原句与损失输入分布同时变化，若要估计样本占比的独立因果效应，需在完全相同新增样本上的配额消融；本轮结论只允许称为“平衡偏好方案”的整体效果。
