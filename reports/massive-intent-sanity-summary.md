# 旧意图分类 SFT 的训练集记忆诊断

这是**训练集诊断**，不是开发集、确认集或泛化成绩。目的仅是验证聊天模板、答案损失和优化配置能否让 Qwen 记住少量标注样本。

从原先 594 条 MASSIVE 中文意图 SFT 训练样本中，固定种子 `20260928` 选 8 个意图、每类 8 条，共 64 条；同一句的归一化文本只出现一次。源训练文件 SHA-256 为 `2975de570be7213d47a5dff753b86f595a60d5edc1d5e38051fb177ca8cf1482`，子集 SHA-256 为 `190bf14b260d261bbde2fb9d07f34f0f8e61d41c19a7659122e68144deb22044`。子集由 [`scripts/prepare_massive_sanity.py`](../scripts/prepare_massive_sanity.py) 生成，原文和训练产物均被 Git 忽略。

| 同一批 64 条训练样本 | 准确率 | macro-F1 |
| --- | ---: | ---: |
| 原始 Qwen2.5-0.5B-Instruct，4-bit | 34.38% | 37.34% |
| QLoRA SFT，**第 32 步检查点** | **95.31%** | **95.18%** |

SFT 设置为学习率 `3e-4`、线性退火、LoRA rank 8、CPU batch 1、梯度累计 4、长度 128；第 32 步相当于看过 128 条样本，即这 64 条约两遍。计划上限 64 步，但在第 32 步诊断达到目的后停止；**没有训练完成 64 步**。第 32 步状态记录 epoch `2.0`。输入模板的检查另由 `scripts/check_sft_template_mask.py` 完成，已确认提示 token 被遮蔽、答案 token 有损失，训练与推理前缀一致。

检查点的第 1 步与第 32 步训练 loss 分别为 `7.1589` 和 `0.0072`；第 32 步的训练 token 准确率为 `1.0`。本地检查点 `adapter_model.safetensors` 的 SHA-256 是 `01a16943d86d6abf201f26718297c565b518979a185295cd153927fc87463843`，权重不随仓库发布。

因此，旧版 594 条训练样本上约 29.63% 的训练准确率不能简单归因于损失遮蔽错误；较高学习率和重复训练能够使小模型记住一个小子集。这个实验**不能**证明新配置在独立语句上更好，也没有解决旧意图分类 SFT 明显落后于同量数据线性基线的问题。下一步采用预注册的四槽位抽取任务，分别报告 Qwen 基座、SFT 和同量数据 BIO 基线的独立开发集表现。
