# 四槽抽取 v2：自然频率留出与无槽误报修复实验

状态：数据和评测方案已冻结；本文件不报告 v2 模型成绩。训练结果必须另行记录，不能把本轮旧确认集的表现当作 v2 成绩。

## 研究问题与上轮发现

v1 QLoRA SFT 在富集目标槽位的 200 条确认集上取得严格实体 micro-F1 60.43%，但 40 条无目标槽位的句子中有 34 条误报，另外 6 条输出无效，按“无效或预测非空”定义的无槽失败率为 40/40。字符 BIO 基线对应为 7/40。v2 重点检验：在保持模型、提示和训练方法基本相同的情况下，增加真实无目标句与含非目标槽的困难负例，能否降低无槽失败，同时保留严格实体抽取能力。

## 数据来源、许可和防泄漏

唯一原始来源是 [MASSIVE 1.0](https://github.com/alexa/massive) 的 `zh-CN` 官方 train 分区；[官方 NOTICE](https://github.com/alexa/massive/blob/main/NOTICE.md) 说明数据许可为 CC BY 4.0。原始归档 SHA-256 固定为 `7df623fd2d300a4d235d6ee5bd396c9a28258d3a0ccb29abdb054506eba153f8`。代码遵守本仓库 Apache 2.0，数据与模型权重分别遵守其各自许可。

脚本 `scripts/prepare_massive_slots_v2.py` 固定种子 `20260929`。先把原句做 NFKC、casefold，删除全部 Unicode 空白和标点后分组；同组目标槽标注冲突则整组剔除。它从候选池排除：

- 官方 `zh-CN` dev/test 分区的全部同组文本；
- 旧意图 SFT 的 594 条训练样本；
- 四槽 v1 的全部 train/dev/confirmation 样本，包含已经用过的旧确认集。

旧文件须与 v1 清单及原始归档逐条核对，v1 清单 SHA-256 固定为 `d6736c2779f00e898dd623911bed08f7c93ab053c287b5ffaaf211a6eee36e32`。本轮只读取旧样本以建立排除集合，不运行旧确认集推理。官方 train 有 11,514 行、11,021 个强归一化组；其中 1,515 个组因旧样本排除，16 个剩余冲突组剔除，得到 **9,490** 个合格组。合格池含 2,855 个有目标组和 6,635 个无目标组，目标阳性率 **30.08%**；无目标组中 3,550 个标有其他类型槽位，3,085 个没有任何槽位标注。

## 切分与锁定文件

先按固定哈希排序，不查看标签配额，取 400 个组为**新确认集**、后续 250 个组为**开发集**。训练组随后从剩余候选抽取：`date`、`time`、`place_name`、`person` 各 64 个目标阳性组，另取 192 个含其他槽位的困难负例及 192 个完全无槽位负例，共 640 条。多目标句只占一个抽样桶，其全部目标标注仍保留。目标槽位 `value` 必须是原句连续子串，目标输出是严格 JSON。

## 预先固定的训练与选择

主实验使用同一 Qwen2.5-0.5B-Instruct 基座、相同四槽提示、4-bit QLoRA，LoRA rank 8 和 `q/k/v/o_proj`，学习率 `3e-4`、batch 1、梯度累计 4、线性退火、训练随机种子 `20260928`、160 optimizer steps，保存第 80 和 160 步。数据抽样种子另为 `20260929`。160 步刚好覆盖 640 条训练样本约一轮。本机训练前已用真实 TRL 路径检查全部 640 条的模板和完成部分遮罩；完整序列最长 **154 token**，因此 `max_length=160` 不截断。评测维持自由贪心生成、输入上限 256 token、输出上限 64 token，不进行 JSON 修复或答案后处理。

在开发集上选择第 80 或 160 步。候选必须同时满足 JSON 合法率、结构合法率、逐字复制合法率各 **≥95%**，以及无槽失败率 **≤30%**；无槽失败指标准答案为空时，模型输出无效或输出非空。合格候选按严格实体 micro-F1 选较高者，平分时选无槽失败率较低者，再平分选较早的第 80 步。若均不合格，记录失败并保持新确认集未打开。训练 loss 和 JSON 合法率不能代替实体成绩。v2 专用评测入口在生成前后核对基座、tokenizer 与 adapter 哈希，并把逐题预测文件哈希写入开发集聚合报告；选择器核对预注册数据文件 SHA、推理时权重哈希及预测文件哈希。

模型、提示、解码、代码、数据和权重 SHA-256 全部写入选择锁之后，才能对 400 条新确认数据各评一次：v2 所选 SFT、冻结的 v1 SFT，以及用 v2 同一 640 条训练数据拟合的字符 BIO 基线；选择锁同时固定 v1 adapter、BIO 模型及开发集报告哈希。确认集不用于再次选择步数或阈值。主要报告严格实体 micro-F1、配对组 bootstrap 差值区间、无槽失败率及其配对区间、无槽误报、有效性、阳性子集 F1、逐句全对和各目标类型 F1。主要比较固定为 `v2_minus_v1`，BIO 为参考；配对 bootstrap 固定 1000 次、种子 `20260929`。若要称 v2 明确改进，须同时满足相对冻结 v1 SFT 的实体 F1 差值区间下界大于 0、无槽失败率下降区间下界大于 0，且新确认集无槽失败率不高于 30%。阳性子集 F1 仅作辅助审查，不用于确认集选模型。未达门槛要如实报告，不能继续用该确认集调参。即使达标，也不等于可以无人复核地上线。

本轮 v2 与 v1 的训练集大小、来源样本和负例比例同时变化，因此成绩差异只能归于整个 v2 方案。若将来要单独证明负例比例的因果作用，应另设相同独特阳性、总训练步数和模型设置的低负例对照，不得事后从新确认集选择对照。

## 选择锁与确认门禁补充

选择器还须核对 `run_manifest.json`：训练文件哈希、完成 160 步、训练种子、学习率、序列长度及保存步数必须与预定方案一致。v2 评测把基座和 adapter 目录中的全部直接文件逐一哈希，包括配置、tokenizer、聊天模板和权重；文件新增或修改都会使选择或确认门禁失败。确认评测只接受固定的锁与输出路径，比较脚本也复核全部依赖代码哈希、模型文件哈希和逐题预测文件哈希。以上检查在打开新确认集前完成。
