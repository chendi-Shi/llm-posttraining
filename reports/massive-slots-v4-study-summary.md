# 四槽抽取 v4：平衡偏好训练未通过门槛

本轮按[预先方案](massive-slots-v4-design.md)在 256 个全新 MASSIVE 官方 train 原句组上完成 64 步 DPO，其中阳性占 50%。[完整机器可读报告](massive-slots-v4-dev.json)记录训练清单、模型、数据与逐题预测的 SHA-256，逐题内容和权重只保留本地。下面是新抽取的 250 条自然频率开发集结果；同一批原句上重新推理冻结的 v3 DPO，对比不使用旧开发集分数。

| 指标 | 冻结 v3 DPO | v4 平衡 DPO |
| --- | ---: | ---: |
| 严格实体 micro-F1 | 52.69% | 44.79% |
| 阳性子集 F1（79 句） | 60.49% | 66.29% |
| 无槽失败（171 句） | 26/171，15.20% | 98/171，57.31% |
| 原文复制合法率 | 97.2% | 92.0% |
| 逐句全对 | 72.0% | 46.8% |

v4 相对 v3 的严格实体 F1 差值为 **−7.90 个百分点**，按原句组配对 bootstrap 1,000 次的 95% 区间为 **−14.18 至 −2.42 个百分点**。v4 多找到 9 个正确实体，但多产生 64 个错误实体；阳性召回的增加不足以抵消无槽误报。无槽失败相对 v3 增加 **42.11 个百分点**，配对 95% 区间显示增加约 **34.50 至 49.12 个百分点**。这些是开发集关联结果，不足以把因果作用单独归给阳性比例，因为 v4 使用了全新的训练原句。

预设七项开发门槛仅有阳性 F1、JSON 合法率和结构合法率通过；总体 F1、无槽失败、复制合法率和相对 v3 的配对 F1 增益均未通过。**因此本轮停止：没有生成选择锁，也没有读取或推理新 400 条确认集；旧 v2 的 400 条确认集同样保持封存。** 不以训练损失、中途检查点或后续规则改写这次失败结论。

事后在这批已看过的开发集上做的预测互补性分析显示：79 条阳性中 v3/v4 都逐句全对 34 条、只有 v4 全对 10 条、只有 v3 全对 1 条；171 条无槽句中只有 v3 答对 60 条。简单并集、交集和按槽位类型拼接都未产生可靠总体收益。这些事后探索不用于本轮门槛，也不构成独立验证。
