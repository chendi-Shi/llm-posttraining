# 四槽抽取 v2：开发集结果与停止决定

**状态：开发阶段停止；400 条新确认集未用于模型推理、评分或选型。** 本报告只依据预先锁定的 MASSIVE 1.0 `zh-CN` 官方 train 来源开发集 250 条。第 80、160 步 SFT 均未通过预定门槛，选择器拒绝生成选择锁。以下数字不能写成确认集成绩或线上效果。

## 数据与模型

按原句 NFKC、大小写折叠、去空白和 Unicode 标点后的组切分，排除 v1 全部样本、旧意图 SFT 样本及官方 dev/test 的同组文本；源归档、训练、开发与未打开确认集 SHA-256 固定于[预先设计](massive-slots-v2-design.md)。训练／开发／确认规模为 **640／250／400**；开发集含 **83** 条目标阳性、**167** 条无目标。训练集含 256 条目标阳性、192 条含非目标槽位的困难负例及 192 条纯负例。全部训练序列经真实模板和 completion 遮罩检查，最长 154 token，`max_length=160`。

Qwen2.5-0.5B-Instruct 使用 4-bit QLoRA SFT，固定第 80／160 步候选。字符 BIO + LinearSVC 用相同的 640 条训练数据作为参考；冻结 v1 SFT 用作原先指定的主要比较对象。自由贪心生成，输入上限 256 token、输出上限 64 token；无 JSON 修复、无预测后处理。严格实体匹配按每句 `(type, literal value)` 多重集计数。

| 系统 | 严格实体 micro-F1 | 目标阳性子集 F1 | 逐句全对 | JSON／结构／逐字复制合法率 | 无目标失败（167 条） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 同量训练 BIO | **61.76%** | 64.62% | **80.0%** | 100%／100%／100% | **9/167，5.39%** |
| 冻结 v1 SFT | 39.77% | **68.63%** | 20.8% | 100%／96.4%／88.4% | 167/167，100%（144 误报＋23 无效） |

| v2 SFT，第 160 步 | 42.17% | 67.01% | 35.6% | 100%／96.4%／91.2% | 126/167，75.45%（112 误报＋14 无效） |

无目标失败定义为：金标准无目标槽位时，输出无效或有效输出含任一目标槽位。单独看 JSON 合法率会掩盖错误类型：第 160 步全部输出可解析为 JSON，但仍有 126 条无目标句失败。四类槽位中，第 160 步 `date/time/place_name/person` F1 分别为 **40.38%／43.75%／54.17%／29.63%**；BIO 分别为 **67.53%／71.79%／49.18%／59.26%**。

开发集按强归一化原句组配对 bootstrap（1,000 次，种子 `20260929`）：第 160 步相对 v1 的实体 F1 点估计 **+2.40 个百分点**，95% 区间 **−1.26 至 +6.54**，不能宣称可靠提升；无目标失败率下降 **24.55 个百分点**，区间 **+18.56 至 +31.14**，但绝对失败率仍为 **75.45%**。第 160 步相对 BIO 的实体 F1 为 **−19.59 个百分点**，区间 **−30.48 至 −9.01**。这些都是开发集分析，不是确认集推断。[四系统开发集配对聚合报告](massive-slots-v2-dev-comparison.json)包含完整计数与区间。

## 预定门槛与停止

预定要求每个 SFT 候选同时满足 JSON、结构、复制合法率各 **≥95%**，无目标失败率 **≤30%**。第 80 步在结构、复制和无目标失败三项上不合格；第 160 步在复制和无目标失败两项上不合格。运行 `scripts/select_massive_slots_v2.py` 得到 `No v2 checkpoint passes all gates; confirmation remains locked`。没有生成 `reports/massive-slots-v2-selection-lock.json`，也没有任何 v2 确认集模型输出或报告。不能用确认集挑新阈值、补选模型或事后宣称 v2 成功。

训练进程在保存第 80 步完整检查点后意外结束，原因未能确认；在第 80 步开发集评测前已记录并公开恢复方案，从该检查点恢复 optimizer、scheduler 和随机数状态，完成原定 160 步。恢复后 adapter 从 `bfloat16` 保存为 `float32`（两者各 192 个 LoRA tensor），因此两个候选间的差异不能只归因于训练步数。模型基座、tokenizer、adapter 与逐题预测在评测前后均按 SHA-256 核验，哈希存于各聚合报告。v2 与 v1 的训练集规模、取样和负例比例同时变化，其差异也不能单独归因于负例比例。

[训练运行清单](massive-slots-v2-training-provenance.json)记录数据、基座、依赖版本和恢复路径；其中 `training_seconds=4980.07` 仅计恢复后的运行，不含首次运行到第 80 步的时间。

## 结论与下一轮方向

v2 整体方案的第 160 步无目标失败率相对冻结 v1 下降，但下降后仍远高于可用门槛，而且严格实体 F1 没有可靠提升。同量 BIO 在总体 F1、格式有效性和无目标处理上更强，因此当前服务仍只保留此前的**意图分类人工复核小模型**；四槽 Qwen SFT 不进入自动抽取或云端部署。

下一轮应先把开发集错误按误报类型、实体类型、格式与复制失败拆解，再预先定义新的训练或解码方案，并在开发集验证后设置新门禁。可以研究独立目标存在性判断、约束输出和更充分的 SFT 训练，但这些目前只是待检验假设。任何从本轮开发集探索出的组合规则都须标为探索性，不得把同一开发集上的最佳分数当成独立证据。现有 400 条确认集仍封存，可在新方案预先锁定且通过开发门槛后使用一次。
