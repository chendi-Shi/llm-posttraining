# 中文四槽抽取 v3：DPO 纠错开发集结果

**结论：未通过预设开发集门槛，停止本轮；400 条确认集仍封存。** DPO 显著降低了无目标槽位句失败，但牺牲了阳性句抽取召回。总体严格实体 F1 的点估计略升，配对置信区间跨 0，不能宣称可靠总体提升。此结果不支持把槽位模型用于自动抽取服务。

## 固定设计与训练产物

本轮针对 v2 SFT 在无槽句上的 126/167 失败，先公开 [v3 方案](massive-slots-v3-design.md)及[复现步骤](../SLOT_V3_RUNBOOK.md)，再从 MASSIVE 1.0 `zh-CN` 官方 train 构造 576 个新候选组。与 v2 train/dev/confirmation 的 1290 个锁定组，以及先前用过的文本组强归一化去重。固定哈希选出 **256** 对偏好样本：四类目标槽位各 16 个阳性、困难负例 96 个、纯负例 96 个。`chosen` 为标注转换的严格四槽 JSON；`rejected` 中 187 个来自冻结 v2 SFT 的真实错误回复，69 个是按事先固定规则构造的错误回复。[聚合审计](massive-slots-v3-preference-audit.json)确认所有偏好对长度不超过 256 token，且与 v2 三切分无组重叠；逐题原文和模型回复不公开。

以 Qwen2.5-0.5B-Instruct 的 v2 第 160 步 SFT adapter 为初始策略和冻结 DPO reference，在 CPU 4-bit QLoRA 下按固定 `beta=0.1`、学习率 `1e-5`、batch 1、梯度累计 4、最大 256 token、种子 `20260930` 训练 **64 optimizer steps（一个 epoch）**。第 32 步只作恢复点，没有参与选型。最终训练清单记录偏好文件 SHA-256 `310c26b37fd7eee7cbfb4876def2d398fcd5f0d188a24da20b24aa474471c450`、起始和冻结参考 adapter SHA-256 `206bc1eee5115e20844e22fa146893c9f651058709c6aff5f15e77ec63f61ce6`，以及最终 adapter SHA-256 `634c83b63b840708e5d8ad63e710fe3a2f219924b3d4cad00ee6f6eb9d721c8a`。最终默认 adapter 保存为 `bfloat16`，起始与冻结参考 adapter 是 `float32`；这一差异已在开发集推理前记录在 [v3 方案](massive-slots-v3-design.md)。64 步优化约 64 分钟，另有参考分数预计算时间，训练清单的 `training_seconds` 只含优化阶段。

## 固定开发集结果

三套模型在相同的 v2 **250 条自然频率开发集**上比较，其中 83 条含目标槽位、167 条无目标槽位。v2 SFT 和同量 BIO 是先前冻结的参考；v3 DPO 只评最终第 64 步。严格实体 micro-F1 按每句 `(槽位类型, 原文值)` 多重集计分，无效输出另计格式失败；无槽失败定义为输出无效或错误地输出目标槽位。

| 系统 | 严格实体 F1 | 阳性子集 F1 | 无槽失败 | JSON / 结构 / 复制合法率 |
| --- | ---: | ---: | ---: | ---: |
| v2 SFT 第 160 步 | 42.17% | 67.01% | 126/167（75.45%） | 100% / 96.4% / 91.2% |
| **v3 DPO 第 64 步** | **47.12%** | **54.75%** | **28/167（16.77%）** | **100% / 98.8% / 96.4%** |
| 同量字符 BIO | 61.76% | — | 9/167（5.39%） | 100% / 100% / 100% |

v3 相对冻结 v2 SFT 的严格实体 F1 点估计增加 **4.94 个百分点**，按原句组配对 bootstrap（1000 次）的 95% 区间为 **−1.67 至 +11.20 个百分点**，跨 0。无槽失败下降 **58.68 个百分点**，配对 95% 区间为 **+50.90 至 +65.87 个百分点**。v3 的无槽失败由 26 条有效误报和 2 条无效输出构成；复制非法 6 条，结构非法 3 条。总体 precision 从 31.88% 升至 48.04%，recall 从 62.26% 降至 46.23%。阳性子集 F1 从 67.01% 降至 54.75%，说明 DPO 学会更常输出空结果，但也漏掉更多真实实体。完整、可复算的聚合数值见 [v3 开发集报告](massive-slots-v3-dpo-dev.json)。本地逐题预测只保存在 Git 忽略目录，其 SHA-256 `fb671defc951f27ac0f653542a2a433206a59b216da6771edd6baf98c4172f46` 写入报告；独立重算严格 F1 和无槽失败率与报告一致。

## 预设门槛与停止决定

8 项门槛中，JSON、结构和复制合法率 ≥95%、无槽失败率 ≤30%、以及相对 v2 SFT 的无槽失败下降配对区间下界 >0，均达成。**三项未达成**：总体严格实体 F1 为 47.12%，低于 ≥55%；阳性子集 F1 为 54.75%，低于 ≥60%；相对 v2 SFT 的配对 F1 增量区间下界为 −1.67 个百分点，未大于 0。因此不生成 v3 选择锁，不对 400 条确认集运行推理，也不使用确认集调整偏好样本、训练步数或门槛。

这轮结果是一个明确的拒判与召回权衡案例。v3 额外使用 256 个训练组，而且保存精度与 v2 不同；不能把差异单独解释为 DPO 目标的因果收益。开发集在设计 v3 前已经用于 v2 错误分析和事后门控探索，即使此次通过门槛，也仍需独立确认。本轮没有通过，所以没有确认集成绩。旧人工复核 HTTP 服务继续使用另一套意图分类小模型；槽位 DPO 既未部署云端，也不具备自动抽取上线资格。

后续若研究方法原因，应先预注册同一 256 个新增组的继续 SFT 对照，并重新设计能保护阳性召回的偏好配比或损失，再用新的开发集做选择。当前封存的 400 条确认集不应被当作调参数据。
