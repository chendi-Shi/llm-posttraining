# 四槽抽取 v6：扩大同源训练集，验证冻结 DPO 门控系统

状态：**主混合系统开发集及封存测试集推理前公开预注册；BIO 开发集评测前已在本地固定方案。** v5 在 600 条独立测试上，固定 BIO＋DPO 门控的严格实体 F1 为 57.21%，相对旧 BIO 的增量 95% 区间下界大于零，但未达到事先要求的 60%。这次不使用 v5 测试逐题结果选训练样本、参数或门控规则，也不修改 v5 的失败判定。

## 单一主假设与对照

主假设：给字符 BIO 更多、类型覆盖更完整且与全部旧研究文本隔离的监督样本，可以提高它与**冻结 v4 DPO** 组成的混合系统的实体 F1。唯一主候选是 **新 BIO 默认回答**，只在冻结 v4 DPO 输出合法、原文可复制、非空四槽 JSON，且完整 assistant 回复（包括结束 token）的平均条件对数概率 **≥−0.08** 时，用 DPO 整个回答替换 BIO。`−0.08` 是 v5 测试前固定的阈值，本轮不重新搜索。

主对照是冻结的 **旧 v5 混合系统**（v2 BIO＋同一 v4 DPO＋同一阈值），在 v6 的同一批新句子上重新推理，不借用 v5 的分数。另分别报告新 BIO、旧 BIO、v4 DPO 单模型；只有新混合系统减旧混合系统是主要配对比较。新旧混合之间训练组、BIO 模型同时变化，因此成功时只能归因于整体方案及新增 BIO 数据，不能声称 DPO 训练本身带来因果提升。

## 数据与防泄漏

来源固定为 MASSIVE 1.0 `zh-CN` 官方 train，归档 SHA-256 `7df623fd2d300a4d235d6ee5bd396c9a28258d3a0ccb29abdb054506eba153f8`，许可 CC BY 4.0。先按 NFKC、大小写折叠、去空白和 Unicode 标点的强原句键分组；排除官方 dev/test 的同组文本、旧意图训练、v1 四槽全部切分，以及 v2–v5 **全部已使用或封存组**，包括 v2/v4 未打开的确认集与 v5 已看测试集。每个旧 manifest 及 v5 测试文件必须匹配固定 SHA-256；旧组通过哈希匹配原句排除，不读取其标签。

固定种子 `20261003`，先从剩余组按哈希排序取**自然频率测试 600 组**，接着自然频率开发 300 组，均不按目标标签重抽。最后从其余组按固定配额取训练 **1,600 组**：`date/time/place_name/person` 各 128 组，含非目标槽的困难负例 544 组，纯负例 544 组。多类型句只按固定顺序进入一个训练桶，但评测保留全部标注。任何组重复、标签冲突、配额不足或指纹不符均应停止。准备脚本为 `scripts/prepare_massive_slots_v6.py`；本地原句、标注、模型和逐题预测在 Git 忽略目录。公开设计与聚合报告不放原句 ID，测试 manifest 不放阳性比例或桶计数。

测试 `data/massive-zh/slots-v6/test.jsonl` 只允许在开发集通过门槛、选择锁发布后，由专用入口读取并运行**一次**。数据文件的哈希及组哈希在任何测试推理前固定。v2、v4 两批各 400 条旧确认集仍封存，不用于本轮选择或验收。测试仍来自 MASSIVE 官方 train，而非真实请求；预训练期间是否见过同源文本无法完全排除。

## 固定训练与推理

新 BIO 对 1,600 条训练句做字符 BIO 标记，沿用 v2 的上下文字符特征、`LinearSVC(C=1.0, class_weight="balanced", max_iter=5000)`、训练器原有随机种子 `20260928` 与合法 BIO 路径解码；只训练一次，不搜索超参数。数据抽样和统计 bootstrap 的种子独立固定为 `20261003`。固定模型、训练文件、源码与依赖指纹后才做开发集推理。旧 BIO、v4 DPO adapter、Qwen2.5-0.5B-Instruct 基座及 tokenizer 均使用已记录的冻结文件。v4 DPO 使用 v5 固定的自由贪心生成：batch 8、输入最多 256 token、输出最多 64 token；无测试时修改门控或修复非法 JSON。

**次级后训练实验**：若 CPU 环境允许，从同一冻结 Qwen 基座对**同一批 1,600 训练组**做 4-bit QLoRA SFT，`learning_rate=3e-4`、batch 1、梯度累计 4、`max_length=256`、种子 `20261003`、400 optimizer steps（约一个训练遍历），仅评固定最终权重，不挑检查点。训练前用真实 tokenizer 检查所有模板和 completion 遮罩及长度；超限则先停止、记录偏离，不能静默截断。SFT 结果单独在开发集报告，与新 BIO 的同样本对照只说明当前配方差异，不替代主候选，也不进入主系统选择。若运行依赖、时间或内存阻止 SFT，明确报告未完成；不以主系统结果代替 SFT 结果。任何 SFT 测试评估必须在 v6 测试开启前另行固定方案和模型指纹，且不影响主验收。

## 选择门槛与独立测试

开发集主候选同时满足以下条件，才可生成选择锁：严格实体 micro-F1 **≥60%**、阳性句子子集 F1 **≥60%**、无目标句失败率 **≤20%**、JSON／结构／原文复制合法率分别 **≥95%**。实体按每句 `(类型, 原文逐字值)` 多重集严格匹配；无目标失败包括无效输出或错误非空输出。开发集用于这个预定门槛核查，不改配额、模型、阈值或规则。未通过就保留失败报告，**不打开测试集**。

通过开发门槛后，先发布只含指纹和配置的选择锁：manifest、train/dev/test 文件 SHA-256，新旧 BIO 权重、v4 DPO adapter 与推理资产 SHA-256，开发报告 SHA-256，阈值、生成参数、bootstrap 规则以及推理和数据准备代码 SHA-256。测试入口须先验证选择锁、各文件指纹和不存在旧输出，再读取测试样本；不允许测试结果覆盖或二次调参。

测试成功需**全部**满足同样四组绝对门槛，且新混合减旧 v5 混合在同批新测试组上的严格实体 F1 **配对 95% 区间下界 >0**。按强归一化原句组 bootstrap：开发 1,000 次、测试 2,000 次，种子 `20261003`。报告五个系统（新旧 BIO、v4 DPO、新旧混合）的总体、阳性、无目标、合法率、四类型 F1 与逐句全对率；次级指标不改变主结论。即使通过，仍需真实请求、延迟、成本和拒判验证才能称为上线可用。
